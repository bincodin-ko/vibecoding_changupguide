# 프로그램 초안 3가지

작성일: 2026-11-19 · 근거: `research/` 폴더의 수집 자료

## 1. 리서치에서 나온 결론

초보 바이브코딩 창업자가 막히는 곳을, 자료에서 자주·강하게 나온 순서로 정리했다.

| 순위 | 막히는 곳 | 근거 요약 |
|---|---|---|
| 1 | **홍보·첫 사용자** | "만들고, 올리고, 지인 좋아요 12개 받고, 끝" 패턴의 반복. 어디에 올릴지 모르고, 커뮤니티는 홍보를 싫어하고, 광고는 클릭만 온다. 한국어 영상 61건 중 만든 서비스의 홍보법을 다룬 것은 1건 |
| 2 | **검증을 건너뛴다** | 다 만든 뒤에야 "이게 남에게도 가치가 있나"를 고민한다. 바이브코딩 맥락의 검증 방법을 다룬 한국어 영상은 표본에서 0건 |
| 3 | **고객·문제 정의가 흐리다** | "누가, 어떤 문제를 겪어서, 이걸 만들었다"를 한 문장으로 못 쓰면 고객이 모이는 곳도 찾지 못한다. 1번 문제의 뿌리 |
| 4 | **단계 사이의 판단 기준이 없다** | 언제 다음 단계로 가고, 언제 고치고, 언제 접는지 모른다. 방문자가 적어 숫자로 판단하기도 어렵다 |
| 5 | **제작 중 막힘** | 기획 없이 프롬프트부터, 같은 에러 반복, 배포·보안·유지보수. 단, 이 영역은 강의·도구가 이미 넘친다 |
| 6 | **수익화의 현실** | 광고 수익은 트래픽 규모가 먼저다. 첫 결제까지 6개월 걸린 사례. 수익 인증 영상과 실제의 간극 |
| 7 | **출시 전 행정·정책** | 사업자등록, 개인정보처리방침, 애드센스·제휴 정책과 고지 문구 |
| 8 | **혼자 버티기** | 출시 후 무반응, 누적되는 AI 비용, 강의 판매자에 대한 불신 |

시장의 빈자리: **제작은 과밀하고, 실제 사람에게 검증받는 실행과 홍보 실행, 그리고 단계 사이의 판단 기준이 비어 있다.** 기존 AI 코파운더 도구는 "AI의 의견"을 주는데, 이는 시장의 증거가 아니라는 비판을 받는다.

## 2. 처음 구상에서 빠져 있던 것

처음 구상은 "문제 정의 → AI 지시 → 빠른 제작 → 검증 → 반복 개선 → 수익화"였다. 자료를 보면 다음이 빠져 있다.

1. **만들기 전 검증** — 검증이 제작 뒤에만 있다. 대화 5명, 한 장짜리 소개 페이지와 대기 신청 같은, 만들기 전에 할 수 있는 검증이 앞에 와야 한다.
2. **고객이 있는 곳을 먼저 정하기** — 홍보는 출시 후의 일이 아니라 아이템을 고를 때 같이 정하는 것이다. "이 고객을 어디서 만날 수 있는가"에 답이 없으면 아이템을 바꾸는 편이 낫다.
3. **측정 준비** — 방문·유입 경로·핵심 행동을 볼 수 없으면 검증 자체가 안 된다. 출시 전에 분석 도구와 "성공으로 볼 숫자"를 정해 둔다.
4. **판단 규칙** — 계속 / 수정 / 중단 기준을 미리 적어 둔다. 없으면 기능만 더 만들게 된다.
5. **재방문 장치** — 광고·트래픽 수익 모델은 다시 오게 만드는 장치(알림, 구독, 즐겨찾기 이유)가 핵심이다.
6. **수익 계산** — "방문자 몇 명이면 월 얼마"를 미리 계산해 본다. 목표 수익에 필요한 트래픽이 비현실적이면 모델을 바꾼다.
7. **출시 전 법·정책 점검** — 사업자등록, 개인정보처리방침, 제휴 링크 고지, 광고 플랫폼 정책. (세부 기준은 공식 기관 확인이 필요하다.)
8. **운영 기본기** — 보안 최소 점검, 백업, AI·서버 비용 상한, 문의 창구.
9. **지속 장치** — 주간 기록, 진행 공개, 같이 가는 동료. 무반응 구간을 넘기는 것이 실제 탈락 지점이다.

그래서 가이드의 전체 흐름은 10단계로 잡는다.

```
0 고객·문제 정의 → 1 만들기 전 검증 → 2 기획·AI 지시 → 3 제작 → 4 출시 준비(측정·법·보안)
→ 5 홍보·첫 사용자 → 6 검증·판정 → 7 개선·재방문 → 8 수익화 → 9 운영·지속
```

## 3. 초안 3가지

세 초안은 같은 10단계 내용을 쓰되, **무엇을 제품의 중심에 두느냐**가 다르다.

### 1안 — 지도형: 관문식 로드맵 사이트

**한 줄**: 10단계를 한눈에 보여 주고, 각 단계의 관문을 통과해야 다음으로 넘어가는 체크리스트형 가이드.

- **사용자가 하는 일**: 내 단계 찾기 → 그 단계의 할 일 3~5개 수행 → 산출물 양식 채우기(고객 한 문장, 한 장 기획서, 출시 점검표, 수익 계산표) → 관문 질문에 답하고 통과
- **각 단계 구성**: 왜 필요한가 / 할 일 / AI에게 그대로 줄 지시문 / 산출물 양식 / 통과 기준 / 흔한 실수(실제 사례 인용)
- **기술**: 정적 사이트 + 브라우저 저장. 서버·로그인 없음
- **제작 기간**: 1~2주 (대부분 글쓰기)
- **수익 경로**: 검색 유입 → 광고·제휴, 양식 묶음 유료 판매
- **강점**: 가장 빨리 만들 수 있고, 검색 유입이 쌓이며, "구조가 불명확하다"는 문제에 바로 답한다
- **약점**: 읽고 끝날 수 있다. 기존 강의·전자책과 형태가 비슷해 차별화가 내용의 질에 전부 달려 있다
- **검증 방법**: 단계 5(홍보) 한 편만 먼저 공개하고, 저장·공유·재방문 수를 본다

### 2안 — 코치형: 내 프로젝트 진단과 다음 행동

**한 줄**: 내 프로젝트를 입력하면 현재 단계를 진단하고, 이번 주에 할 일 3개와 필요한 초안(기획서, 홍보 글, 인터뷰 질문)을 만들어 주는 AI 코치.

- **사용자가 하는 일**: 프로젝트 설명 입력 → 진단 결과 확인 → 이번 주 과제 수행 → 결과(방문 수, 대화 수, 반응)를 기록 → 계속 / 수정 / 중단 판정을 받음
- **핵심 설계 원칙**: AI는 아이디어를 평가하지 않는다. **증거를 받아 오게 시키고, 가져온 증거로만 판정한다.** ("대화 5명 중 몇 명이 이 문제를 지난달에 실제로 겪었나?")
- **기술**: 웹앱 + AI 연동 + 로그인·저장. 운영 비용 발생
- **제작 기간**: 4~6주
- **수익 경로**: 무료 진단 + 월 구독
- **강점**: 개인화. "판단 기준이 없다"는 4번 문제를 직접 해결. 사용 기록이 쌓여 떠나기 어렵다
- **약점**: 만들 것이 가장 많고 AI 비용이 든다. 비슷한 해외 도구가 있다. 과제를 내줘도 사용자가 실행하지 않으면 가치가 없다
- **검증 방법**: 앱 없이 사람이 직접 5명을 2주간 코칭해 보고(메신저로), 실제로 과제를 수행하는지와 돈을 낼 의사를 확인한다

### 3안 — 실행형: 14일 첫 사용자 스프린트

**한 줄**: 가장 아픈 홍보·검증만 판다. 하루 20분 과제로 14일 동안 고객 대화 5건과 첫 사용자 10명을 만드는 실행 도구.

- **사용자가 하는 일**: 고객 한 문장 작성 → 고객이 모이는 곳 3곳 선정 → 매일 과제 1개(질문에 답하기, 문제에 대한 글 쓰기, 한 명에게 직접 연락하기) → 유입·반응 기록 → 14일 뒤 판정
- **들어가는 것**:
  - 한국 채널 지도: 채널별 성격, 홍보 규정, 맞는 말투, 금지 행동
  - 채널별 글 초안 생성(제품 자랑이 아니라 문제 이야기로)
  - 유입 경로 표시가 붙은 링크 생성과 결과 기록판
  - 인터뷰 질문지와 대화 기록 양식
  - 14일 뒤 계속 / 수정 / 중단 판정표
- **기술**: 정적 사이트 + 브라우저 저장으로 시작. 글 초안 생성만 AI 연동(선택)
- **제작 기간**: 2~3주
- **수익 경로**: 스프린트 1회 무료, 채널 지도 전체판과 반복 사용은 유료. 또는 기수제 유료 참여
- **강점**: 1·2번 문제에 정면 대응. 한국 채널에 맞춘 실행 안내는 경쟁이 거의 없다. 결과가 숫자(대화 수, 사용자 수)로 나와 효과를 증명하기 쉽다
- **약점**: 범위가 좁아 "문제 정의부터 수익화까지"라는 처음 그림의 일부만 다룬다. 채널 규정은 계속 바뀌어 유지 관리가 필요하다. 홍보 글 생성이 스팸 도구로 쓰이지 않게 "기여 먼저" 규칙을 과제에 넣어야 한다
- **검증 방법**: 채널 지도 한 장과 14일 과제표를 문서로만 만들어 5명에게 써 보게 한다

### 비교

| | 1안 지도형 | 2안 코치형 | 3안 실행형 |
|---|---|---|---|
| 겨냥하는 문제 | 구조가 안 보인다 | 판단 기준이 없다 | 홍보·검증을 못 한다 |
| 제작 기간 | 1~2주 | 4~6주 | 2~3주 |
| 운영 비용 | 거의 없음 | AI·서버 비용 | 거의 없음 |
| 차별화 | 약함 | 중간 | 강함 |
| 효과 증명 | 어려움 | 중간 | 쉬움(숫자) |
| 처음 그림과의 일치 | 전체 | 전체 | 일부 |

## 4. 추천

**3안을 중심에 두고, 1안을 얇은 뼈대로 붙여 시작한다. 2안은 뒤로 미룬다.**

- 가장 아픈 곳이 홍보·검증이고, 그곳이 시장의 빈자리다. 전 과정을 고르게 다루면 이미 넘치는 "만드는 법" 콘텐츠와 경쟁하게 된다.
- 1안의 10단계 지도는 "지금 어디에 있는지"를 알려 주는 입구로만 쓴다. 각 단계는 한 화면 분량으로 얇게, 5·6단계만 깊게 만든다.
- 2안은 사람들이 어느 단계에서 실제로 막히는지 데이터를 본 뒤에 만든다. 지금 만들면 추측으로 만드는 것이다.

**운영 중인 할인 정보 사이트를 첫 번째 사례로 쓴다.** 그 사이트에 14일 스프린트를 직접 적용하고 숫자를 공개하면, 가이드의 내용 검증과 홍보 콘텐츠, 신뢰가 한 번에 생긴다. 리서치에서 사람들이 찾는 것은 성공담이 아니라 비용과 실패까지 공개하는 솔직한 기록이었다.

**이 가이드도 만들기 전에 검증한다.** 순서는 다음과 같다.

1. 초보 바이브코딩 창업자 5~10명과 대화한다(이번 리서치는 전부 2차 자료다).
2. 채널 지도 1장과 14일 과제표를 문서로 만든다.
3. 5명에게 써 보게 하고, 끝까지 하는지와 사용자가 실제로 생기는지 본다.
4. 그 결과로 제품 범위를 확정하고 제작을 시작한다.

## 5. 정해야 할 것

- **대상**: 코딩을 모르는 비개발자인가, 개발은 되는데 사업을 모르는 개발자인가. 둘은 막히는 곳이 다르다.
- **형태**: 무료 공개 가이드(트래픽 수익)인가, 유료 도구인가.
- **이 가이드의 고객은 어디에 있는가**: 가이드 자신도 2번 누락 항목에 답해야 한다.
