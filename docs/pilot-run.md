# 문서판 시험 진행 안내 (진행자용)

참가자가 보는 문서판: https://claude.ai/artifact/BZmfoWT9yCc9rVFhXT3VMe

통과 기준과 전체 계획은 [sprint-spec.md](sprint-spec.md) 9장에 있다. 이 문서는 진행자가 실제로 할 일만 적는다.

## 1. 나눠 주는 방법

- 참가자마다 **자기 사본 하나**를 준다. 기록판을 각자 채워야 하므로 한 문서를 같이 쓰지 않는다.
- 문서판 이름을 눌러 내보내기에서 Google Docs 사본(또는 Word·PDF)을 만든 뒤, 참가자 수만큼 복사해 링크를 보낸다.
- 사본 이름은 "14일 스프린트 — [참가자 이름]"으로 하고, 진행자에게 편집 또는 댓글 권한을 열어 달라고 한다.
- 원본을 고치면 사본에는 반영되지 않는다. 시험 중에 고친 내용은 참가자에게 따로 알린다.

## 2. 참가자 모으기

대상은 AI로 서비스를 만들었는데 사용자가 거의 없는 비개발자다. 본인을 포함해 5명.

찾을 곳: 아는 사람, 바이브코딩 카페의 서비스 소개 게시판에 "만들었는데 쓰는 사람이 없다"고 쓴 사람. 게시판에 모집 글을 올리기 전에 그 카페의 공지를 확인한다. 개별 연락이 금지된 곳에서는 하지 않는다.

제안 문구(자기 말투로 고쳐 쓴다):

> 안녕하세요. [어디]에 올리신 [서비스 이름] 글을 봤습니다. 저도 AI로 [내 서비스]를 만들었는데 쓰는 사람이 없어서 같은 고민을 하고 있어요. 그래서 하루 20분씩 14일 동안 고객 5명과 이야기하고 첫 사용자를 찾아보는 과제 모음을 만들었고, 저 포함 다섯 명이 먼저 해 보려고 합니다. 비용은 없고 판매하는 것도 없습니다. 대신 하시면서 어디서 막혔는지만 알려 주시면 됩니다. 관심 있으시면 문서를 보내드릴게요.

## 3. 14일 동안 할 일

| 때 | 할 일 |
|---|---|
| 시작 전날 | 사본 전달. 준비 과제 3개를 먼저 하도록 안내 |
| 매일 | 한 줄 확인 메시지: "오늘 과제 하셨나요? 막힌 곳 있으면 한 줄만 알려 주세요." 답이 없어도 재촉하지 않는다 |
| 4~5일차 | 대화 요청에서 가장 많이 멈출 것으로 예상한다. 멈춘 사람에게 무엇이 망설여지는지 묻고 그대로 적는다 |
| 7일차 | 각자의 고친 고객 한 문장을 받아 본다 |
| 14일차 | 기록판의 "14일 합계"와 "끝난 뒤 한 가지만"을 받는다 |
| 끝난 뒤 | 15분 통화로 가장 쓸모 있었던 과제와 가장 하기 싫었던 과제를 듣는다 |

진행자는 과제를 대신 해 주거나 글을 고쳐 주지 않는다. 문서만으로 할 수 있는지를 보는 시험이다.
